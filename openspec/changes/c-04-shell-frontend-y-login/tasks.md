# Tasks — C-04 `shell-frontend-y-login`

Protocolo para **todas** las tareas: escribir primero el test que falla (RED), implementar lo mínimo para pasarlo (GREEN), agregar **al menos dos casos adicionales por comportamiento** (TRIANGULACIÓN), refactorizar con la suite en verde (REFACTOR) y volver a ejecutar `npm --prefix frontend test`. Ninguna tarea se da por terminada con un test roto. Hay dos excepciones explícitas al RED: **1.1** es safety net (se ejecuta antes de escribir producción) y **7.2** es verificación final (incluye revisión manual de los mockups). Toda dependencia del navegador se inyecta: no se instala `jsdom`, no se agrega ninguna dependencia y ningún test importa `main.ts` con efectos de módulo.

El `frontend/tsconfig.json` (líneas 18-24) impone `strict`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`, `erasableSyntaxOnly`, `noUnusedLocals` y `noUnusedParameters`: no usar `enum`, importar tipos con `type` y no leer indexes sin chequear su existencia.
