## Desvíos del apply

1. Proyección JPQL con `Instant`, convertida a `TurnoAfectadoDto` con offset en el servicio (`design.md` D1/D6); JPQL no puede construir `OffsetDateTime`.
2. Los servicios resuelven el dueño con `OdontologoActual.id()` y no reciben `odontologoId` como parámetro, pese a la redacción de tasks 3.1/3.3; es la regla dura de seguridad y D4.
3. El filtro `desde`/`hasta` de `GET /api/bloqueos` se aplica en memoria con intersección semiabierta; suficiente para el volumen de la demo.
4. La exclusión de `CANCELADO` en `turnosAfectados` la garantiza la consulta JPQL, no un filtro del servicio.
5. Horarios no tiene id de recurso: en `AislamientoConfiguracionIT` el 404 ajeno/inexistente se compara en prestaciones y bloqueos; para horarios se prueba que un `odontologoId` inyectado no cambia el dueño.
6. Sin CSRF, una escritura sin sesión responde 403 (CSRF corre antes que autorización); el test de 401 envía token CSRF válido sin sesión. No se cambió la cadena de filtros.
